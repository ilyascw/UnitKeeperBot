# ТЗ: экран перевода юнитов (miniapp)

## Контекст
Бэкенд готов (`POST /balances/transfers`, `GET /balances/transfer-candidates`, `GET /balances/transactions`), UI отсутствует. Часть скоупа [issue-04](issue-04-balances-progress-and-content.md). Экран встраивается в существующий `BalanceScreen` (или отдельный экран, доступный с него) — там уже показывается свой баланс.

## Пользовательский флоу
1. Пользователь на экране баланса видит свой текущий баланс и кнопку **«Перевести юниты»**.
2. Открывается экран/шторка выбора: список активных участников группы (кроме себя) с их текущим балансом — это список кандидатов на перевод.
3. Пользователь выбирает получателя → вводит сумму.
4. Подтверждение перевода → успех/ошибка → обновлённый баланс.
5. Ниже (или отдельным табом) — история операций (лента переводов и других транзакций баланса).

## Экран 1 — Выбор получателя
- Список: аватар, имя, текущий баланс каждого участника.
- Поиск/фильтр не обязателен (группы небольшие), но не мешает.
- Пустое состояние: "В группе больше никого нет" (если кандидатов нет).

## Экран 2 — Ввод суммы и подтверждение
- Показать: кому переводим (имя, аватар), свой текущий баланс.
- Поле ввода суммы:
  - только положительные числа, до 2 знаков после запятой;
  - валидация на фронте: сумма > 0.
- Кнопка "Перевести" — активна только при валидной сумме.
- Состояния ошибок от бэкенда, которые нужно показать пользователю понятным текстом:
  - сумма ≤ 0 → «Введите сумму больше нуля»
  - перевод самому себе (не должно быть возможно по UI, т.к. получатель уже исключён из списка)
  - получатель не является активным участником группы → «Пользователь больше не в группе»
  - у отправителя нет активной группы → edge case, обычно недостижим из UI
- Успех: показать тост/экран подтверждения с новым балансом отправителя и суммой перевода.

## Экран/блок 3 — История операций
- Пагинированный список транзакций (лимит по умолчанию 50, есть `has_more` → подгрузка следующей страницы / "показать ещё").
- Для каждой строки:
  - тип операции (перевод, спринт-расчёт, ручная корректировка — text label);
  - сумма со знаком (+/-), цветом (зелёный/красный по аналогии с `balanceColor`);
  - для переводов — контрагент (имя пользователя-отправителя/получателя);
  - описание (опционально, если есть);
  - дата/время.
- Пустое состояние: «Пока нет операций».

## Данные с бэкенда (справочно, задаёт объём контента)
- Баланс: число с 2 знаками после запятой, может быть отрицательным.
- Список кандидатов: имя + аватар + баланс.
- Транзакция: тип, сумма со знаком, контрагент (может отсутствовать), описание (может отсутствовать), дата.

## Вне скоупа
- Массовые/групповые переводы.
- Отмена перевода.
- Фильтрация истории по типу/периоду (можно как будущее улучшение).
